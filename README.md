# CamelliaFlowers — CRM для квіткового бізнесу

CamelliaFlowers — веб‑додаток на Django 6 для обліку клієнтів, товарів та замовлень у квітковому магазині. Проєкт підтримує авторизацію, роботу з замовленнями (включно з історією зміни статусів), аналітику та інтеграцію з Cloudinary для зображень товарів.

## Вимоги
- Python 3.13+
- PostgreSQL (для локального запуску основного додатка)

## Швидкий старт (локально)
1. Клонувати репозиторій та перейти у директорію проєкту.
2. Створити та активувати віртуальне середовище.
3. Встановити залежності:
   - Мінімально необхідні: `pip install -e .`
   - Для розробки (з тестами і лінтерами): `pip install -e .[dev]`
4. Створити `.env` у корені проєкту (приклад змінних є в існуючому файлі). Не зберігайте реальні секрети в репозиторії.
5. Застосувати міграції і запустити сервер:
   ```bash
   python -m django migrate --settings=config.settings
   python -m django runserver --settings=config.settings
   ```

## Налаштування середовища
- Бойові/локальні налаштування беруться з `src/config/settings.py` і `.env`.
- Для тестів використовується окремий модуль налаштувань `src/config/settings_test.py` (SQLite in-memory, швидкі хешери паролів, локальна пошта, стабільна конфігурація Cloudinary).

## Тести
Ми використовуємо `pytest` + `pytest-django` і збираємо покриття `coverage`:

- Запуск усіх тестів:
  ```bash
  pytest -q
  ```
- Детальний звіт покриття у терміналі:
  ```bash
  pytest --cov=src --cov-report=term-missing
  ```

Налаштування `pytest` і `coverage` знаходяться в `pyproject.toml` (секції `tool.pytest.ini_options`, `tool.coverage.*`). Тестові файли живуть у відповідних пакетах `src/apps/<app_name>/tests/`.

Детальні пояснення щодо структури та запуску тестів — у файлі `TESTING.md`.

## Pre-commit хуки
У репозиторії налаштований `pre-commit` з гачками:
- Базові перевірки: `trailing-whitespace`, `end-of-file-fixer`, `check-merge-conflict`, `check-yaml`.
- Лінт/формат: `ruff` (автофікси) та `ruff-format`.

Інсталяція:
```bash
pip install -e .[dev]
pre-commit install
```
Ручний запуск на всьому репозиторії:
```bash
pre-commit run --all-files
```

## Структура проєкту (скорочено)
- `src/apps/accounts` — кастомна модель користувача (login по email) та профілі.
- `src/apps/clients` — клієнти, лічильники, VIP‑логіка.
- `src/apps/products` — товари, категорії, стан машини товару, Cloudinary зображення.
- `src/apps/orders` — замовлення, товари в замовленні, історія статусів, списки/деталі/видалення, AJAX‑ендпоїнти.
- `src/config` — базові налаштування та `settings_test.py` для тестів.

## Безпека
- Не комітьте справжні секрети до репозиторію. Для локального запуску використовуйте `.env` і локальні значення.
- У тестах налаштовані безпечні значення Cloudinary і SQLite в пам’яті.
